# RespondKit 0.6.4

Status: prepared, not published. A merged PR does not publish SDK artifacts.

## Release notes

Every string RespondKit shows comes from the translated catalog. 0.6.3 translated the empty state, the "Ask us anything" subtitle and the attach menu; the email ask, composer, delivery statuses, retry and error states, and accessibility labels stayed English. They now follow the user's language on iOS, Android, web and React Native, with the 0.6.3 fallbacks.

- **Native views.** SwiftUI looks every string up in RespondKitUI's bundle instead of the host's main bundle. Compose reads string resources and formats transcript dates in the activity locale.
- **Store text.** The body of an attachment-only message, the length and closed-conversation errors, and the logout, history-save and unverified-identity errors come from the catalog through the new `RespondKitStrings` on the Swift and Kotlin stores. `RespondKitScreen` sets it, and a store used without a screen keeps English.
- **Ten new keys** in all 51 locales: `respondkit_message_too_long`, `respondkit_message_limit`, `respondkit_closed_start_new`, `respondkit_logout_failed`, `respondkit_history_save_failed`, `respondkit_done`, `respondkit_unread_reply`, `respondkit_reconnecting`, `respondkit_conversation_label`, `respondkit_identity_unverified`.
- **Errors.** Network, HTTP, protocol and storage failures show catalog text ("Support request failed.", "Upload failed", "Support chat could not be started.") instead of the SDK's English diagnostics or server messages. The Swift, Kotlin and React Native stores keep the original text in a new `errorDetail`.
- **Default title.** When the host passes no title, iOS, web and React Native show the translated "Support", as Compose already did.
- **Guard.** `pnpm ready` fails if any file in the SwiftUI or Compose module gains an English literal, including lowercase labels, interpolated labels and transcript helpers. Exception messages are exempt, because they are no longer shown.

## Upgrade and compatibility

Use `0.6.4` for the npm packages, `v0.6.4` for SwiftPM and `0.6.4` for Maven. No protocol change.

- Swift: `RespondKitScreen(title:)` is now `String?` (default `nil`, meaning the catalog's "Support"); existing calls compile unchanged.
- `errorMessage` (native) and `error` (React Native) no longer carry raw diagnostics; read `errorDetail` for logging.
- An attachment-only message is sent with the translated "Attached files" body, so operators see it in the customer's language.
