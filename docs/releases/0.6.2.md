# RespondKit 0.6.2

Status: prepared, not published. A merged PR does not publish SDK artifacts.

## Release notes

A client patch for three problems found in ReceiptGenie's iOS and Android apps with 0.6.1.

- **No email-ask flash.** The native stores and the React Native store now wait until the contact lookup for the current identity has finished before asking for an email (`asksForEmail`). The ask never appears when the host supplied an email or the server already stores one. Before, iOS, Android and React Native showed the ask for a moment while the stored contact was being fetched. The web widget already waited, and new tests guard it.
- **Android attach button.** The Compose composer's text "Attach files" button above the input is now a paperclip icon button to the left of the message field. It matches the web and iOS composers.
- **Already-sent agent replies.** `/approve` and the **Approve draft** / **Reject draft** commands now recognise an agent reply that was already sent (its Discord message, or its `msg_agent_` id) and answer "That agent reply was already sent to the customer at <time>; it can't be approved or retranslated. Use /reply to send a correction." instead of "not an agent draft". The Discord timestamp shows in each operator's own timezone. IDs that aren't agent replies still get "not an agent draft". Inbound translation is unchanged.
- **Translated strings.** The SwiftPM `RespondKitUI` target and the Compose module now bundle the resources generated from `localization/messages`. The empty state, the "Ask us anything" subtitle and the attach menu read from that catalog on both platforms. Other native strings remain English literals for now. The catalog ships English only. Other languages need a reviewed `messages/{locale}.json`.

## Upgrade and compatibility

Use `0.6.2` for the npm packages, `v0.6.2` for SwiftPM and `0.6.2` for Maven. No protocol change. The `/approve` answer needs the API deployed.

- `RespondKitStore.asksForEmail` (Swift, Kotlin state) and `SupportSnapshot.asksForEmail` (React Native) are new. Custom screens that show their own ask should use them instead of checking the email for null.
- Android: the Compose module's own `res/values/strings.xml` is gone, and its strings come from the shared catalog. `respondkit_new` no longer exists (use `respondkit_new_conversation`), and `respondkit_intro` now holds the longer intro line, with the short one in `respondkit_intro_short`. Hosts that override either name must update their overrides.

## Operator checklist

1. Deploy the API: `cd apps/api && pnpm exec wrangler deploy --env staging`.
2. Publish GitHub release `v0.6.2`, which runs the npm publish workflow. Publish Maven Central per `docs/native/releases.md`.
3. Point ReceiptGenie 2.9.0 at 0.6.2.
