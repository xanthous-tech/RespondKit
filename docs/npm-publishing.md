# npm publishing

RespondKit publishes three public packages in dependency order:

1. `@respondkit/protocol`
2. `@respondkit/api-client`
3. `@respondkit/react`

The packages keep direct TypeScript source exports inside this pnpm workspace. `publishConfig.exports` rewrites the npm tarballs to compiled ESM and declaration files generated by Vite+ Pack. The React tarball also retains its selected source files because Tailwind CSS v4 scans them while processing `@respondkit/react/styles.css` in the host application.

## Local release gate

```sh
pnpm ready
pnpm build:npm
pnpm check:npm
pnpm pack:npm
```

Vite+ Pack runs publint and Are the Types Wrong for every package. `check:npm` then installs the real tarballs into a clean temporary npm consumer, type-checks a React integration, imports the runtime modules, builds the widget and Tailwind stylesheet with a clean Vite application, and verifies that no `workspace:` range leaked into a published manifest.

## Bootstrap release

Staged and trusted publishing require an existing npm package, so version `0.1.0` was
published interactively once. The bootstrap procedure was:

1. confirm the root MIT `LICENSE` and the `MIT` SPDX identifier in all three package manifests;
2. run the local release gate above;
3. authenticate an npm account with publish access to the `respondkit` organization and 2FA enabled;
4. run `vp exec tsx scripts/validate-npm-release.ts v0.1.0`;
5. from a directory outside the monorepo, publish the three tarballs from `artifacts/npm` in the dependency order listed above with `npm publish <absolute-tarball-path> --access public`.

The final command runs outside the monorepo because the repository deliberately pins pnpm through `devEngines`; npm correctly rejects direct commands from the workspace root.

## Trusted publishing

After the first versions exist, configure the trusted publisher on each package in npm:

- provider: GitHub Actions;
- organization: `xanthous-tech`;
- repository: `RespondKit`;
- workflow: `publish.yml`;
- allowed action: `npm publish`.

After a GitHub release is published, the workflow publishes to npm only after the full
repository gate, tarball checks, matching lockstep versions, and license metadata pass. It
uses npm OIDC and does not require a long-lived npm token. Because the source repository and
packages are public, trusted publishing also generates npm provenance attestations.

For subsequent releases, update all three package versions together, merge the change, and publish a GitHub release whose tag exactly matches `v<version>`.
