RespondKit adds in-app support to React, React Native, SwiftUI, and Android Compose apps. Customers talk in your app; your team replies from Discord. The merged implementation also supports email follow-up and file attachments.

## What is available

Customer sessions, conversation history, read receipts, local greetings, email capture, native device context, and attachments share one API. Email follows up on unread operator replies after a default ten-minute delay. Incoming email replies return to the same thread. Message translation is optional and operator-requested.

**Check the release before installing.** Merging a feature does not publish its npm or Maven package, deploy its database migrations, or configure its email domain. [Release and rollout](/docs/rollout) explains the order and how to test it.

Support-agent job claiming and operator reply APIs are still proposed. The current customer API does not provide operator access. See [Support agents](/docs/agent-api).

## One conversation, multiple channels

1. The client opens a session scoped to your product's inbox.
2. A customer message appears in that client's transcript and a Discord forum thread.
3. An operator uses `/reply`. Translation is optional.
4. The client displays the reply and acknowledges that transcript as read.
5. If the reply remains unread and email is configured, the scheduled sender emails it. A read acknowledgement cancels pending delivery.
