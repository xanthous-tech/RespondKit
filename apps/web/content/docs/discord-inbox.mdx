RespondKit maps one customer conversation to one Discord forum post. Operators can read translated customer messages and keep the entire support history in the thread.

## Required channel permissions

The RespondKit bot needs permission to:

- view the forum channel;
- create posts;
- send messages in posts;
- read post history;
- manage posts;
- add reactions;
- use application commands.

## Customer read receipts

A bot-owned ✅ on a “Reply sent” message means the customer has displayed that reply in an open, visible chat. Sending a reply, polling unread counts, or keeping the chat closed does not mark it read. Each reply keeps its own checkmark once read; a newer reply stays unchecked until it is displayed.

This requires the React SDK 0.4.1 or later and the bot’s Add Reactions and Read Message History permissions. The widget sends an authenticated transcript cursor to the API and retries failed receipts. The API persists that cursor before adding the reaction. A once-per-minute sweep recovers Discord failures and receipts that arrive before the bot’s reply is posted. A delayed checkmark does not require resending the reply.

## Reply to a customer

Run the command inside the relevant support thread:

```text
/reply message:Please reopen the app and try the export again.
```

RespondKit acknowledges the command immediately, translates the English reply into the customer language, and publishes the result to the widget. The bot also mirrors the operator reply into the thread so the conversation is easy to scan.
