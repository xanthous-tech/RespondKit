RespondKit maps one customer conversation to one Discord forum post. Customer messages and sent replies appear in the thread, and operators have three commands when answering customers directly: `/reply`, **Translate to English**, and `/activity`.

## Required channel permissions

The RespondKit bot needs permission to:

- view the forum channel;
- create posts;
- send messages in posts;
- read post history;
- manage posts;
- add reactions;
- use application commands;
- attach files for long private translation previews and activity timelines.

## Customer read receipts

A bot-owned ✅ on a "Reply sent" message means the customer displayed that reply in an open, visible chat. Sending a reply, polling unread counts, or keeping the chat closed does not mark it read. Each reply keeps its own checkmark once read; a newer reply stays unchecked until it is displayed.

This requires the React SDK 0.4.1 or later and the bot's Add Reactions and Read Message History permissions. The widget sends an authenticated transcript cursor to the API and retries failed receipts. The API persists that cursor before adding the reaction. A once-per-minute sweep recovers Discord failures and receipts that arrive before the bot's reply is posted. A delayed checkmark does not require resending the reply.

## Reply to a customer

Run `/reply` inside the relevant support thread:

```text
/reply message:Please reopen the app and try the export again.
```

The customer receives the exact text you entered. Translation is optional:

```text
/reply message:Please reopen the app. translate:customer
/reply message:Please reopen the app. translate:hi
```

`customer` uses the language you last named for the thread, or else a reliably detected one; translating a newer customer message never replaces an operator-named language. If it is unknown, translate an incoming message first or supply a language name or code (`Burmese`, `简体中文`, `my`). Browser locale is not treated as proof of the customer's language.

A requested translation must succeed before the reply becomes available to the customer. If it needs review, RespondKit shows a private preview with a **Send this translation** button, and nothing is sent until you confirm. When delivery finishes or fails, the private message updates to say whether the reply was sent or not sent. If a reply was not sent, run `/reply` again; the customer receives it once.

## Translate an incoming message

Right-click or long-press a customer message and choose **Apps → Translate to English**. A translation appears as a reply to its original message. Repeated requests reuse the saved result. Translation failures are private and do not mark the original message as failed.

Translation must be enabled for the inbox using `TRANSLATION_ENABLED_INBOXES`, with a working Gemini credential. Enable the commands for your operator role under **Server Settings → Integrations → RespondKit**. No additional Discord OAuth scope or Message Content intent is needed.

## Customer activity

When PostHog is configured for the inbox, `/activity` posts the customer's latest 20 pageviews and product events in the Discord thread. Use `count:50`, `minutes:30`, `kind:pageviews`, or `until:last_message` to narrow the snapshot. Supplying minutes without count allows up to 100 events. Long timelines include a text attachment.

Activity stays in Discord and is not sent to the customer. PostHog failures do not affect replies. The bot needs Attach Files permission for long timelines; hosts already supplying a PostHog distinct ID need no client update.
